# 从 RoboTwin 迁移现状 → 追平并超越 RoboDojo 的工作量评估

> 评估日期:2026-08-26
> 对标对象:RoboDojo(arXiv 2607.04434,2026-07 发布)
> 基线:本仓库 RoboTwin 迁移 P0 完成后的实际代码状态

## 一、两个端点在哪里

### 当前位置(基于代码库实际状态)

- ✅ P0 迁移骨架 100%:资产管线(5 本体 URDF 10/10 通过、139 物体资产)、Bridge 回放、HDF5/Zarr 录制、种子搜索、域随机化、OMPL 规划、渲染三档配置、526 测试
- ⚠️ 规划器 ~70%(cuRobo 只做了接口适配,未端到端)、任务层 **~10%**(0 个原生任务)、策略训练 0%(只有数据格式)
- 🚫 M4 渲染标定 / M5 五十任务回归 / M6 性能调优全部 blocked on GPU

### RoboDojo 的全貌(arXiv 2607.04434,2026-07)

- 42 个仿真任务 + 18 个真机任务,3 种双臂本体(ARX X5 / Piper / Piper X)
- Isaac Sim/Lab 上配置驱动(YAML)任务栈 + 带语义/affordance 标注的资产库(刚体/关节/柔体)
- **异构并行**(同一进程内不同 env 跑不同场景/任务)+ 多 GPU 分片
- 技能库(grasp/place/handover/insert/open/close/stack/push_up)+ cuRobo v2 自动合成 demo;VR 遥操作兜底
- XPolicyLab 统一策略接口(30+ 策略接入)、seed 可控评测协议、leaderboard 聚合
- RoboDojo-RealEval 真机平台(固定硬件工装 + 布局回放 + 云端评分)

## 三、"超越"的杠杆在哪(这是 Genesis 的主场)

追平只是复刻,超越应该打在 RoboDojo(Isaac 系)的结构性弱点上:

1. **柔体/布料维度** — Genesis 原生 MPM/SPH/FEM,RoboDojo 的柔体只是 ClothesNet 资产 + 估计参数。加一个 Isaac 做不了的 deformable 任务维度,边际成本约 8–12 人周,差异化最大。
2. **吞吐与成本** — Madrona 批量渲染 + 确定性 CPU 后端 + MUSA 支持:同等评测规模下 GPU 成本远低于 Isaac Sim(已有渲染三档配置的底子)。
3. **零许可证、云原生** — Isaac Sim 绑 NVIDIA 栈;本项目定位 cloud-robotics-sim,把 #5 的多进程分片做成真正的云端弹性评测服务(leaderboard-as-a-service),是 RoboDojo eval-only 发布没覆盖的。
4. **自动任务生成** — 已有 seed_search + 资产清单工具链,再进一步做配置空间的任务自动扩增,任务数从"移植 42 个"变成"生成 400 个"。

## 四、关键前置与风险

- **硬性前置:GPU/CUDA 环境**。cuRobo 端到端、M4 渲染标定、M6 吞吐调优、异构并行全部 blocked,没有 GPU 这张表无从启动。
- **最大单项风险是 #2/#3(任务 + 标注)**,占近一半工作量,本质是人肉数据工,建议优先把 #1 配置框架和标注工具做扎实,让任务移植变成流水线。
- RoboDojo 是 2026-07 刚发布的活跃项目且在持续扩任务,追平目标会移动——所以差异化(第三节)比逐项对标更重要。

## 五、一句话总结

仿真侧追平约 55–95 人周(3–4 人团队 4–6 个月,前提是 GPU 到位);真机侧另加 20–30 人周 + 硬件;真正的"超越"不在任务数量,而在柔体维度、吞吐成本和云原生评测服务上。
