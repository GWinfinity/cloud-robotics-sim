EFE（Embodied First Exam）全量迁移梳理

对标对象：Embodied First Exam （arXiv:2611.12177，2026-11-09；代码与任务包 mll-lab-nu/embodied-first-exam，MIT）。 本文档把 EFE 的 35 套件 / 47 机器人 / 1,156 任务 / 2,288 测试（456 核心） 全部登记入册，并给出逐套件、逐机器人的迁移映射与分批路线。 机器可读登记册：data/efe/（生成物 data/efe/registry.json，CI 门 uv run python tools/build_efe_registry.py --check）。

1. EFE 是什么、迁移什么

EFE 是面向 coding agent 的统一机器人评测：每个任务里 agent 写程序控制 冻结场景中的机器人，三种评测设定——Privileged（全状态+无限重置，交 轨迹/程序）、Standard（仅传感器观测、默认不可重置，仿真作为服务）、 Realtime（Standard + 时钟不停）。任务包为 Harbor 格式： instruction.md（目标/约定）+ task.toml（预算/元数据）+ environment/instance.json（哈希冻结的实例）+ tests/（隔离判分器）。 上游逐套件 README 精确记录了动作布局、成功判据与世界坐标系——这是移植时 最重要的规格来源。

迁移到本项目 = 在 Genesis 1.4.6 上重建每个套件的场景、机器人、成功 判据，接入现有 core/（Registry / Composer / Task）执行栈与 configs/tasks/*.yaml + data/suites/*.yaml 评测协议，使 EFE 任务可以 在本仓库复跑、复评。

3. data/efe/ 布局与工具链

data/efe/
  suites/<suite>.yaml   # 36 条策划记录：efe.*（论文事实）+ project.*（迁移映射）
  tasks/<suite>.json    # 36 份上游任务清单（task.toml 解析物，生成物）
  robots.yaml           # 47+4 机器人资产来源对账表
  registry.json         # 生成物：合并视图 + totals + warnings（build 工具产出）
tools/fetch_efe_inventory.py    # 快照 -> tasks/*.json（手动、离线；不走网络）
tools/build_efe_registry.py     # 合并 + 校验；--check 为 CI 门

三层数据相互独立校验：策划 YAML（论文 Table 2 人工登记）↔ 任务清单 JSON （上游 task.toml 解析）↔ 论文总数常量（内嵌 build 工具）。任何一层漂移 --check 即失败；机器人必须登记 robots.yaml 来源才能通过结构校验。

8. 分批路线

P0 — 对齐与冒烟（1–2 周）

  • T0：RoboWits 与 EFE 任务清单对账（marvin-bimanual ↔ 现有 port 的命名与 判据），补 data/suites/efe_smoke.yaml。

  • 登记册本身就是 P0 交付：--check 进 CI，后续任何套件迁移必须同步改 data/efe/suites/*.yaml 的 project.status。

P1 — T1 单臂先遣（约 200 任务）

状态（2026-11-17 更新）：MetaWorld+ 首个垂直切片引擎级通过。 已交付：core/success.py 判据扩展（distance_threshold 轴加权 / axis_window 目标锚点相对模式 / in_region / count_in_region / body_point_near，TDD 44 过）；tools/compile_efe_suite.py 编译器 （MJCF include 解析 + 世界坐标合成 + 判据表→知识库→schema v1 配置， --check CI 门）；runtime/efe.py 注册（sawyer MJCF 机器人 / efe_tabletop 场景 / efe_static 基任务）；tests/efe/ 双层门 （离线 nop-fail 契约 + Genesis 引擎冒烟，slow）。 MetaWorld+ 50/50 全部编译并通过双层门（100%，2026-11-17）——上游 wheel 镜像 后近目标族批量解锁：判据句逐字转写自 instruction.md，目标语义取自 env .py 常量（goal_space/self.goal/TARGET_RADIUS），代表点注明”spec 级、 非冻结实例值”；nop 门累计拦截 3 处 XML 声明位姿≠任务初始位姿 （plate-slide-back×2/push-back/button-press-topdown，均以 init_override 或退回 pending 修正）。登记册状态 partial。其余 24 个：机构类 （door/window/drawer/faucet/dial/lever/button-topdown）需逐 env 翻译 reset 语义（door 为平移语义已核实）；reach×2 需 ee 谓词；stick×2 需 接触谓词；lever-pull/dial-turn 需角度/旋转目标。

保真度分级（写入每个编译配置的 fidelity 注释）： spec = 判据与参数按上游 README/instruction 的规格逐条转写、初始布局 按上游随机化范围重建（非位精确）；frozen = 应用上游 instance.json 冻结位姿。MetaWorld+ v1 为 spec 级；判据句一律从上游 instruction.md 的 “## Success”/”## Scoring” 节摘编进 data/efe/compile/<suite>.specs.md 后人工转写，禁止凭记忆写阈值。

两个套件的路线修正（读上游 README 后的发现）：

  • RoboPaint 的成功判据是纸面墨迹的图像指标（IoU/boundary-F/覆盖/ stray）+ 笔画过程规则，本质是 2D 光栅评分（libmypaint 体系）， 不是 Genesis 物理谓词——需要独立的评分器移植（raster scorer + 笔画样本记录），保留在 P1 但单独立项。

  • LIBERO-MAX 依赖 robosuite 位精确状态哈希（AVX-512 数值核）与 LIBERO-PRO 资产（CC-BY-4.0）及 8 类事件运行时——Genesis 重建属于 spec 级降级（事件语义可移植，位精确不可承诺），排在 P1 末位。

  • 机器人资产 100% 就绪的套件优先：MetaWorld+(sawyer 公开 MJCF)、 LIBERO-MAX / VLABench / RoboPaint / LabUtopia(franka 在库)——这四个就 是 193 任务；加 KinDER(5)、Safety-Exam 的 franka/ur5e 子集。

  • 每个套件按 §9 的 DoD 落地；P1 完成时 ported 任务数应 ≥ 200。

P2 — T1 双臂/灵巧/人形 + T2（约 480 任务）

9. 套件级 DoD（”ported” 的判定标准）

一个套件标记 status: ported 需全部满足：

  1. 套件内全部任务以 schema v1 配置落地 configs/tasks/efe/<suite>/*.yaml， 并由 data/suites/efe_<suite>.yaml 汇总；

  2. 机器人资产过 embodiment 认证门（gold/silver，或登记过的 compose 装配）；

  3. 成功判据按上游 README 的规格逐条实现为 verifier（可执行，非注释）；

  4. nop 必失败、参考解/规则解可通过（对齐 EFE 的入册自检）；

  5. 三设定映射明确：Privileged ↔ 本仓库 evaluation runner；Standard / Realtime ↔ 仿真即服务（复用 robowits_ported 的 service 经验）；

  6. data/efe/suites/<suite>.yaml 的 project.status 改为 ported， --check 通过，套件文档链入本文档。

10. 约束与风险（对齐 AGENTS.md）

  • 测试零网络：登记册工具链全部离线（fetch_efe_inventory.py 为手动 步骤，CI 不跑）；端口判分不得访问模型 API。

  • 资产许可：BEHAVIOR 数据包 / HSSD / BlenderKit 等有许可门或 HF gated 数据集，只能以「显式、可禁用、可 mock」的方式接入；Menagerie/公开 URDF 转换须记录出处（沿用 conversion_report.json 机制）。

  • 不重判安全语义：Safety-Exam / ManiGuard 的拒止判定是规则 verifier， 与项目 SafetyViolationError 边界一致，不得用元数据替代运行时保护。

  • 性能现实：AutoBio 500Hz、VLABench 单控步最多 100 物理步等预算约束 要在任务配置里显式声明，Genesis 步进成本需逐套件实测（记 docs/troubleshooting.md）。

  • 上游漂移：上游仓库持续演进（robodojo +6 dirs 已发生）；刷新 tasks/*.json 必须重跑 --check 并人工复核 diff。
