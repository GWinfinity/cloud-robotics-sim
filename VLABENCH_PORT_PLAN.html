VLABench 迁移方案与可行性（dm_control → Genesis 1.4.6 / quadrants）

套件登记：data/efe/suites/vlabench.yaml（T1，36 任务 / 72 测试 / 2 核心）。 本文回答一个问题：dm_control 任务能否迁移到基于 quadrants 的 Genesis， 并给出迁移路径、保真度分级与缺口清单。状态真相以 data/efe/registry.json 与 tools/build_efe_registry.py --check 为准。

0. 结论

可行，按 spec 级保真落地。 dm_control 在 VLABench 中只是 Python 组合层 （composer 拼装场景、可观测封装、should_terminate_episode 判据）；其产出的 任务 XML 全部是标准 MJCF，由 MuJoCo 编译。Genesis 1.4.6 的 MJCF 导入器本身 委托官方 mujoco 包完成编译（genesis/utils/mjcf.py::build_model → mujoco.MjModel.from_xml_string），再把编译产物转成 Genesis 刚体实体交给 quadrants 求解器。因此：

  • MuJoCo 能编译的 MJCF（含 dm_control 生成物）→ Genesis 能读；

  • quadrants 是仿真后端，与导入路径正交；同一导入栈已在 MetaWorld+ （sawyer MJCF）全量通过双层门，本仓库有先例。

1. 依赖面调查（2026-11-17，上游 cf588fe / 资产 08d7a44）

层

事实

迁移含义

任务 XML

obj/meshes/** 下 36 实例引用的组件 XML（counter/shaker/billiards…）全是标准 MJCF：mesh geom + 材质贴图 + visual/collision 分组；billiards 等是空 worldbody 的资产库

直接 MJCF 导入；资产库式组件需像 VLABench composer 那样以自由体实例化

场景 XML

scenes/<name>/（18 个房间，studyroom.xml 等）：贴图 + 房间网格 + 地板

同上；实例 scene.name 指向目录，XML 文件名 ≠ 场景名

机器人

franka_emika_panda/panda.xml（GitHub，MIT）：7 臂关节 <general> 执行器（dyntype=none biastype=affine，gainprm/biasprm = P 到位置目标）+ 2 指 <position> 执行器；无关节限位（文档值见 instruction）；肌腱/耦合全注释掉

执行器模型与导入器原生支持的分式 force = gain·ctrl + bias₀ + bias₁·pos + bias₂·vel 完全一致；限位需在控制器层用文档值钳制

引擎选项

instance.json 的 integrator=implicitfast、impratio=10、multiccd=enable、流体 density/viscosity

MuJoCo 专属，不映射；Genesis 用自家求解器参数，保真度记 spec 级

任务逻辑

dm_control composer + should_terminate_episode（contain/above/pour/press 等谓词，部分带朝向语义如 “tip past horizontal”）

Python 层，必须在 Genesis 侧重实现为 core/success.py 条件；判据句逐字转写自 instruction.md / grade.py（DoD §9.3）。谓词语义源（上游 MIT，已镜像至 .efe_stage/OpenMOSS_VLABench-git 稀疏检出与 data/efe/upstream/images-vlabench/）：VLABench/tasks/condition.py 谓词库 + hierarchical_tasks/** 逐任务 should_terminate_episode + EFE grade.py/vlb_tool.py（GHCR efe:vlabench-files-0.5.2 层）

动作接口

9 维绝对位置目标 @10Hz（0.1s = 100 物理步，dt=0.001）

映射到 Genesis 关节位置控制（control_dofs_position）

冻结机制

model_sha256 / initial_state_sha256（MuJoCo 3.2.2 位精确）

Genesis 重建不可复现 MuJoCo 哈希；冻结改为 Genesis 侧实例钉住（init 位姿来自 instance.json，等价 compile_efe_suite 的 init_override）

3. 资产镜像（”镜像其任务 XML”的落点）

  • tools/fetch_vlabench_assets.py：幂等镜像，三源—— EFE 任务文件（instance.json + instruction.md + grade.py）→ data/efe/upstream/tasks/vlabench/；组件/场景 XML + 引用资产（HF lerobot/vlabench-assets@08d7a44）→ assets/vlabench/；panda 机器人 （GitHub MIT）→ assets/vlabench/robots/franka_emika_panda/。

  • 许可：VLABench 资产集不允许再分发 → 镜像只留本地并 gitignore （assets/vlabench/），入仓库的只有工具和 PROVENANCE 记录；HF 端点可配 （HF_ENDPOINT，默认 huggingface.co 不通时走 hf-mirror.com）。

  • 手动步骤（与 fetch_upstream_assets.py 同级），CI/测试不得调用。

4. 缺口与对策

  1. 位精确不可承诺：frozen 保真（上游哈希冻结）不可达，v1 一律 spec 级——判据按上游逐字、初始布局用 instance.json 冻结位姿。与 MetaWorld+ v1 同一分级。

  2. 谓词覆盖面：core/success.py 现有 Distance/Pose/AxisWindow、in_region、 count_in_region、body_point_near、ee_near、staged。已补 VLABench 首批两个 （2026-11-17，TDD 65 过）：above_region（VLABench AboveCondition：z ≥ 平台 原点 + 足迹圆/盒）与 tipped（PourCondition：实体局部 top/bottom 站点 世界 z 差 > 阈值，”tip past horizontal”）。后续按需增补：contain 的 足迹+高度带语义（FlatContainer.contain：根点落于足迹且 0 < z−center.z < z_threshold，如 select_fruit 的 0–0.1 m 带）、IsGraspedCondition、 ButtonPressedCondition、OnCondition（接触对+z 上限）。

  3. 关节限位：XML 无限位 → 在 VLABench 任务控制器Wrapper 按 instruction 文档值钳制 9 维动作（Panda 限位逐关节列出）。

  4. 保活/语义漂移：36 个冻结实例逐个跑 nop 门（起始状态不命中判据）+ 引擎冒烟（Genesis 上实例化合、落体稳定、位置控制可动）。
